# 文档 AI 帮写设计文档

**适用范围**：Metis Note 编辑器 AI 辅助写作能力

---

## 1. 背景

Metis Note 已具备基于 Tiptap 的富文本编辑能力和 LLM 模型配置管理能力，但目前 LLM 仅用于连接测试，尚未集成到文档编辑流程中。用户在写作时经常遇到"不知道接下来怎么写"的问题，需要一种轻量的方式让 AI 阅读当前文档上下文并帮助续写。

本设计的目标是：

> 用户在编辑文档时输入 `/`，从弹出菜单中选择"AI 帮写"，系统自动读取文档上下文，调用 LLM 生成内容，用户确认后插入文档。

## 2. 设计目标

1. 在编辑器中通过 `/` 快捷方式唤起 AI 帮写，无需离开编辑器。
2. AI 自动读取文档标题和已有内容作为上下文，用户无需手动复制粘贴。
3. 生成结果以流式方式实时展示在光标位置下方，让用户看到写作过程。
4. 生成完成后用户可以 **确认插入** 或 **取消丢弃**，不会自动修改文档。
5. 复用现有已启用的 LLM 模型配置，不要求用户额外配置。

## 3. 设计原则

### 3.1 就地操作

AI 帮写的触发、预览、确认都在编辑器内完成，不弹出独立窗口或跳转页面。

### 3.2 上下文自动化

系统自动提取文档标题、正文内容和光标位置作为 LLM 的输入上下文，用户不需要手动选择或描述。

### 3.3 用户掌控

AI 生成的内容必须经过用户确认才会插入文档。生成过程中用户可以随时取消。

### 3.4 非侵入

AI 帮写是编辑器的可选增强，不改变现有编辑流程。没有配置模型或模型不可用时，菜单项显示为禁用状态并给出提示。

## 4. 用户流程

### 4.1 触发

1. 用户在编辑模式下，在文档正文中输入 `/`。
2. 编辑器在光标位置下方弹出斜杠命令菜单。
3. 菜单中包含 **AI 帮写** 选项（带 AI 图标）。
4. 用户点击或通过键盘选择该选项。

### 4.2 生成

1. 系统删除用户输入的 `/` 字符。
2. 在光标位置下方显示 AI 生成面板，包含：
   - 生成状态提示（"正在思考…" → "正在写作…"）
   - 流式输出的文本预览区域
   - 取消按钮
3. 系统收集文档上下文，调用已启用的 LLM。
4. LLM 响应以流式方式逐步显示在预览区域中。

### 4.3 确认或取消

生成完成后，面板底部显示两个操作按钮：

| 操作 | 快捷键 | 行为 |
| --- | --- | --- |
| 确认插入 | `Enter` 或 `⌘+Enter` | 将生成内容插入到光标位置，关闭面板 |
| 取消 | `Escape` | 丢弃生成内容，关闭面板，光标回到原位 |

生成过程中按 `Escape` 立即中断生成并关闭面板。

## 5. 斜杠命令菜单设计

### 5.1 触发条件

- 编辑器处于编辑模式。
- 用户在段落开头或空行输入 `/`。
- 光标在空的文本节点或段落起始位置。

### 5.2 菜单内容

首批菜单只包含一个 AI 相关命令，未来可扩展：

| 命令 | 图标 | 说明 | 可用条件 |
| --- | --- | --- | --- |
| AI 帮写 | Sparkles | AI 根据上下文续写文档 | 有已启用的 LLM 模型 |

当没有已启用的模型时，该命令项显示为灰色禁用状态，附带提示文字"请先在设置中配置模型"。

### 5.3 菜单行为

- `/` 后继续输入可过滤菜单项（模糊匹配命令名称）。
- 支持 `↑` `↓` 键盘导航和 `Enter` 选择。
- 点击菜单外部或按 `Escape` 关闭菜单。
- 选择命令后菜单关闭，`/` 及后续过滤字符被删除。

## 6. 上下文收集策略

### 6.1 收集内容

系统自动收集以下信息作为 LLM 输入：

| 内容 | 来源 | 用途 |
| --- | --- | --- |
| 文档标题 | `note.title` | 帮助 LLM 理解写作主题 |
| 光标前的文本 | 编辑器中光标位置之前的纯文本 | 主要上下文，LLM 基于此续写 |
| 光标后的文本 | 编辑器中光标位置之后的纯文本 | 可选参考，帮助 LLM 保持连贯 |

### 6.2 上下文长度限制

- 光标前文本最多取 **3000 字符**。
- 光标后文本最多取 **1000 字符**。
- 如果超过限制，从距离光标最远的部分截断。
- 上下文长度限制作为内部常量，不暴露给用户。

### 6.3 Prompt 构造

系统使用内置的 system prompt 和 user prompt 模板：

**System Prompt：**

```
你是一个写作助手，帮助用户续写文档内容。根据文档标题和已有内容，自然地继续写作。
要求：
- 保持与已有内容一致的语言、风格和语气。
- 直接输出续写内容，不要输出解释、标题重复或元描述。
- 输出纯文本，不要使用 Markdown 格式标记。
```

**User Prompt 模板：**

```
文档标题：{title}

已有内容：
{contextBefore}

[请从这里续写]

{contextAfter}
```

## 7. AI 生成面板设计

### 7.1 面板位置

面板显示在光标所在行的下方，作为编辑器内的浮动元素。面板不遮挡光标前的内容。

### 7.2 面板状态

| 状态 | 面板内容 |
| --- | --- |
| 等待响应 | 脉冲动画 + "正在思考…" |
| 流式生成中 | 实时文本 + "正在写作…" + 取消按钮 |
| 生成完成 | 完整文本 + 确认按钮 + 取消按钮 |
| 生成失败 | 错误提示 + 重试按钮 + 关闭按钮 |

### 7.3 面板样式

- 面板带有浅色背景（如 `#f8fafc`）和细边框，与编辑器正文区分。
- 生成文本使用与编辑器正文一致的字体和行高，方便用户预判插入效果。
- 面板最大高度限制为 **320px**，超出时显示滚动条。
- 面板左侧有一条紫色竖线标识（如 `#7c3aed`），表明这是 AI 生成内容。

## 8. 内容插入策略

### 8.1 插入位置

确认后，生成的文本插入到用户触发 `/` 时的光标位置。

### 8.2 插入格式

- 生成内容作为纯文本插入，继承光标所在位置的段落格式。
- 如果生成内容包含多个段落（`\n\n` 分隔），每个段落作为独立的段落节点插入。
- 插入后光标移动到插入内容的末尾。

### 8.3 撤销支持

- 插入操作作为一个整体记录在编辑器的 undo 栈中。
- 用户可以通过 `⌘+Z` 撤销整个 AI 插入。

## 9. 技术架构

### 9.1 需要新增的模块

| 模块 | 位置 | 职责 |
| --- | --- | --- |
| 斜杠命令扩展 | `src/components/editor/slash-command.ts` | Tiptap 扩展，监听 `/` 触发命令菜单 |
| AI 生成面板 | `src/components/editor/ai-write-panel.tsx` | 浮动面板 UI，展示生成状态和结果 |
| LLM 推理 IPC | `electron/main/ipc/llm-inference.ts` | 新增 IPC 通道，处理推理请求 |
| LLM 推理服务 | `electron/main/services/llm-inference.ts` | 调用 LLM API 并返回流式结果 |
| Preload 桥接 | `electron/preload/index.ts` 扩展 | 新增 `llm.streamChat` 方法 |

### 9.2 IPC 通道设计

新增以下 IPC 通道：

**请求-响应通道：**

| 通道 | 方向 | 用途 |
| --- | --- | --- |
| `llm:startStreamChat` | renderer → main | 发起流式推理请求，返回 `streamId` |
| `llm:cancelStream` | renderer → main | 取消正在进行的流式请求 |

**事件推送通道：**

| 通道 | 方向 | 用途 |
| --- | --- | --- |
| `llm:streamChunk` | main → renderer | 推送一个文本片段 |
| `llm:streamEnd` | main → renderer | 推送生成完成信号 |
| `llm:streamError` | main → renderer | 推送生成错误信息 |

### 9.3 Preload 桥接 API

在 `window.metisNote` 上新增 `llm` 命名空间：

```typescript
window.metisNote.llm.startStreamChat(params: {
  systemPrompt: string
  userPrompt: string
}) => Promise<{ streamId: string }>

window.metisNote.llm.cancelStream(streamId: string) => Promise<void>

window.metisNote.llm.onStreamChunk(callback: (streamId: string, chunk: string) => void) => () => void
window.metisNote.llm.onStreamEnd(callback: (streamId: string) => void) => () => void
window.metisNote.llm.onStreamError(callback: (streamId: string, error: string) => void) => () => void
```

`on*` 方法返回取消订阅函数，组件卸载时调用以清理监听。

### 9.4 推理服务设计

推理服务负责：

1. 获取当前已启用的 LLM 模型配置。
2. 根据模型的 `configType` 和 `protocol` 选择调用方式：
   - `managed-local`：通过 `node-llama-cpp` 本地会话直接推理。
   - `builtin` / `custom`（OpenAI 协议）：调用远程 `/v1/chat/completions` 接口，`stream: true`。
   - `builtin` / `custom`（Anthropic 协议）：调用远程 `/v1/messages` 接口，`stream: true`。
3. 将流式响应拆分为文本片段，通过 IPC 事件推送到渲染进程。
4. 处理取消、超时和错误。

### 9.5 数据流

```
用户输入 /
  → 斜杠命令菜单弹出
  → 用户选择"AI 帮写"
  → 编辑器收集上下文（标题 + 光标前后文本）
  → 构造 system prompt + user prompt
  → 调用 window.metisNote.llm.startStreamChat()
  → IPC 到 main 进程
  → 推理服务调用 LLM（本地或远程）
  → 流式 chunk 通过 IPC 事件推回 renderer
  → AI 生成面板实时显示文本
  → 用户点击确认
  → 编辑器在光标位置插入文本
  → 触发 onContentChange 保存
```

## 10. 异常处理

### 10.1 无可用模型

- 斜杠菜单中 AI 帮写项显示为禁用。
- 提示文字："请先在设置 > 智能设置中配置并启用一个模型"。

### 10.2 模型请求失败

- 面板显示错误状态："生成失败，请检查模型配置或网络连接"。
- 提供 **重试** 按钮（使用相同上下文重新请求）和 **关闭** 按钮。

### 10.3 生成超时

- 远程模型请求设置 **60 秒** 超时。
- 本地模型请求设置 **120 秒** 超时（本地推理可能较慢）。
- 超时后显示错误提示并提供重试。

### 10.4 生成中断

- 用户按 `Escape` 或点击取消时，立即发送 `llm:cancelStream`。
- 已接收的部分文本被丢弃，不插入文档。
- 面板立即关闭。

### 10.5 文档上下文为空

- 如果文档标题和正文均为空，仍然允许触发 AI 帮写。
- Prompt 中上下文部分留空，LLM 将基于空文档生成开头内容。

## 11. 分阶段落地

### Phase 1：基础推理能力

- 新增 LLM 流式推理 IPC 通道和服务。
- 支持 OpenAI 协议远程模型的流式调用。
- 支持 Anthropic 协议远程模型的流式调用。
- Preload 桥接 API。

### Phase 2：斜杠命令与 AI 帮写

- Tiptap 斜杠命令扩展。
- AI 生成面板 UI。
- 上下文收集和 prompt 构造。
- 确认/取消交互。
- 内容插入和撤销支持。

### Phase 3：本地模型支持

- 接入 `node-llama-cpp` 本地会话的流式推理。
- 本地模型与远程模型使用统一的 IPC 接口。

### Phase 4：体验优化

- 支持用户在触发 AI 帮写前输入额外指令（如"帮我写一段总结"）。
- 生成结果支持"重新生成"。
- 多轮交互：对生成结果追加修改指令。

## 12. 总结

文档 AI 帮写是编辑器内的就地辅助写作能力：

- 用户通过 `/` 唤起斜杠命令菜单，选择"AI 帮写"触发。
- 系统自动收集文档标题和光标前后内容作为 LLM 上下文。
- LLM 流式生成内容，实时显示在光标下方的浮动面板中。
- 用户确认后内容插入文档，取消则丢弃，文档不受影响。
- 复用现有模型配置，支持远程模型和本地托管模型。
