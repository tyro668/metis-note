# 本地模型一键使用设计文档

**适用范围**：Metis Note 本地模型能力  
**相关文件**：`design/model/local-model-design.json`、`design/model/builtin-models.json`

---

## 1. 背景

普通用户不关心 GGUF、量化、`node-llama-cpp`、本地端口、运行参数、接口协议这些实现细节。他们真正想要的是：

> 选择一个模型，点击一次按钮，然后立即开始使用。

本设计文档定义一套**完整的、本地模型一键可用方案**：用户只需要做最少的选择，系统自动完成下载、安装、运行、配置、绑定、启用与恢复。用户在任何界面中都不需要看到本地 IP 地址、端口号或接口协议。

## 2. 设计目标

### 2.1 核心目标

1. 让普通用户只需要 **一次添加/下载操作** 就能开始使用本地模型。
2. 把协议、端口、IP 地址、模型标识、运行参数、量化等技术细节完全从用户界面中隐藏。
3. 自动完成模型文件下载、运行时准备、完整性校验、安装、配置创建、运行启动与可用性检测。
4. 让本地模型在应用中的使用体验尽量接近远程内置模型：能添加、启用、切换、删除、恢复。
5. 首批内置支持 **Qwen3.5 4B** 与 **Qwen3.5 9B** 两个模型下载入口。

### 2.2 非目标

1. 首个版本不做用户自定义 Hugging Face 仓库浏览器。
2. 首个版本不支持任意文件夹手动扫描外部模型作为主路径。
3. 首个版本不默认暴露复杂调优界面，如 `ctx-size`、`gpu-layers`、线程数等。
4. 首个版本只聚焦 **GGUF 聊天模型**，不扩展到 embedding、reranker、图像模型等。

## 3. 设计原则

### 3.1 一键优先

正常路径必须是单一主操作，不允许普通用户在添加过程中填写协议、接口地址、端口或模型标识。

### 3.2 零配置默认

只要用户选择的是系统内置推荐的本地模型，系统就必须自动决定：

- 量化版本
- 运行时后端准备
- 下载地址
- 安装路径
- 内部运行路由
- 运行上下文默认参数
- 模型配置绑定关系

### 3.3 渐进暴露

复杂选项不能消失，但必须隐藏在"高级设置"后面。默认界面只展示用户真正需要理解的信息。

### 3.4 自动恢复

下载中断、应用重启、模型切换、运行失败等异常必须能自动恢复或给出单击重试，而不是让用户重新从头配置。

### 3.5 单一事实源

模型文件、运行时、用户可见的本地模型条目、当前运行中的服务实例必须通过内部 ID 关联，不能依赖用户手工输入的字符串来维持一致性。

## 4. 用户承诺

本地模型功能对用户的承诺：

> 在"设置 > 智能设置 > 本地模型"中，选择一个推荐模型，点击"添加并下载"，应用会自动完成其余所有步骤，下载完成后即可直接使用。

### 4.1 用户只需要做的事

1. 进入本地模型页面。
2. 在推荐模型中选择一个模型。
3. 点击 **添加并下载**。

### 4.2 系统自动完成的事

1. 根据当前平台准备兼容的 `node-llama-cpp` 运行时。
2. 自动选择推荐量化版本。
3. 自动检查磁盘空间和基本资源条件。
4. 自动下载 GGUF 模型文件并准备运行时环境。
5. 自动校验文件完整性。
6. 自动安装到应用托管目录。
7. 自动创建本地模型配置（`configType: "managed-local"`）。
8. 自动绑定内部运行时路由和请求模型名（用户不可见）。
9. 自动启动本地推理运行时。
10. 自动检查运行时是否可用。
11. 在没有活动本地模型时自动启用新模型。

### 4.3 不向普通用户展示的内容

以下内容在托管本地模型的完整生命周期中**绝不**向普通用户展示：

- 协议类型（OpenAI 兼容 / Anthropic 兼容）
- 内部运行路由或兼容层地址
- 内部端口或路由细节
- 请求模型标识（即 API 调用中的 `model` 字段）
- 运行命令与启动参数
- 量化版本选择器
- 运行时后端细节
- API Key 输入框（托管模型不需要 Key）

**关键约束**：托管本地模型的添加入口是专用的本地模型页面，不通过通用模型添加/编辑弹窗操作。

## 5. 整体体验设计

### 5.1 页面入口

入口位于：

`设置 > 智能设置 > 本地模型`

该页面是一个专门的本地模型管理界面，不沿用远程模型的通用编辑弹窗。

### 5.2 页面结构

页面由四个区域组成：

1. **推荐模型**
   - 展示可一键添加的本地模型。
   - 默认突出推荐模型与资源需求。
2. **已安装模型**
   - 展示已安装、可启动、可启用的本地模型。
3. **下载队列**
   - 展示下载、校验、安装的实时进度。
4. **运行状态**
   - 展示当前本地运行时是否已启动、正在使用哪个模型、最近一次异常状态。

### 5.3 推荐模型列表展示字段

默认只展示下列字段：

| 字段 | 说明 |
| --- | --- |
| 模型名称 | 如 Qwen3.5 4B、Qwen3.5 9B |
| 推荐标记 | 推荐、标准、较高质量 |
| 预计下载大小 | 帮助用户感知下载成本 |
| 预计内存需求 | 帮助用户感知设备是否适合 |
| 当前状态 | 未安装、下载中、安装中、可用、使用中 |
| 主按钮 | 添加并下载 / 启动 / 立即使用 |

不展示协议、接口地址、端口、供应商、量化细节。

### 5.4 主流程状态

用户能看到的状态统一为：

- 未安装
- 准备中
- 下载中
- 安装中
- 启动中
- 可用
- 使用中
- 需要处理

这些状态必须是面向用户的产品语言，而不是技术语言。

## 6. 一键使用流程

### 6.1 标准成功路径

1. 用户点击某个模型的 **添加并下载**。
2. 系统执行预检：
   - 磁盘空间
   - 平台兼容性
   - 运行时可下载性
   - 基础内存提示
3. 预检通过后，系统创建一个安装任务。
4. 系统自动下载模型文件并准备运行时。
5. 下载完成后执行校验。
6. 校验通过后将文件移动到托管目录。
7. 系统生成 `configType: "managed-local"` 的本地模型配置并与安装产物绑定。
8. 系统通过 `node-llama-cpp` 加载模型并创建上下文会话。
9. 系统完成一次内部就绪检查。
10. 就绪检查通过后，将模型状态设为 **可用**。
11. 如果当前没有启用中的本地模型，则自动启用该模型。

### 6.2 已安装再次使用路径

如果某模型已安装：

- 主按钮从"添加并下载"变为"启动"或"立即使用"。
- 不再重复下载。
- 若模型已在运行，则直接允许切换为当前使用模型。

### 6.3 切换模型路径

如果用户切换到另一个本地模型：

1. 系统停止当前运行中的本地模型运行时。
2. 系统启动目标模型运行时。
3. 系统切换内部绑定关系。
4. 界面更新为新的"使用中"状态。

用户不需要手动停止旧模型，也不需要手动改接口配置。

## 7. 自动化规则

### 7.1 自动选择规则

**模型推荐规则**

- **Qwen3.5 4B** 作为默认推荐项，适合大多数设备。
- **Qwen3.5 9B** 作为更高质量选项，仅在设备资源较充足时推荐。

**量化选择规则**

- 每个模型在首个版本只暴露一个**经过验证的推荐量化版本**。
- 对普通用户不提供量化选择。
- 若未来提供高级模式，也只在高级模式下开放量化切换。

**运行时选择规则**

- 系统根据当前平台自动使用随应用分发的 `node-llama-cpp` 运行时。
- 用户不选择运行时版本，不需要理解运行时差异。

### 7.2 自动配置规则

系统必须自动完成以下配置：

- 生成内部安装记录 `installedArtifactId`
- 创建 `configType: "managed-local"` 的用户可见本地模型配置
- 绑定内部调用路由（不暴露给用户）
- 绑定请求模型名
- 绑定运行时会话信息
- 在首次安装成功后自动启用

### 7.3 自动恢复规则

- 网络瞬时失败时自动退避重试。
- 应用重启后恢复未完成下载。
- 启动失败时保留已安装文件，并提供一键重试。
- 校验失败时删除损坏文件并重新下载。
- 如果主仓库不可用，自动切换到已验证的备用仓库。

## 8. 技术架构

### 8.1 核心模块

系统由五个核心模块组成：

1. **模型目录服务**
2. **制品存储服务**
3. **下载管理器**
4. **运行时管理器**
5. **本地模型配置绑定层**

### 8.2 模型目录服务

模型目录服务负责提供系统内置的本地模型列表，包括：

- 模型展示名称
- 模型家族
- 参数规模
- 推荐等级
- 推荐量化版本
- 主下载源与备用下载源
- 文件大小
- 资源建议
- 校验信息

其职责是向 UI 暴露"可选模型"，而不是让 UI 自己拼接下载地址。

### 8.3 制品存储服务

所有托管文件统一存储在：

`userData/metis-note-models/`

目录结构如下：

| 路径 | 作用 |
| --- | --- |
| `catalog/` | 模型与运行时目录数据 |
| `downloads/` | 临时下载文件和断点续传文件 |
| `models/` | 已安装模型文件 |
| `runtime/` | 预留运行时缓存与元数据 |
| `logs/` | 本地模型运行日志 |
| `registry.json` | 安装记录与关联关系 |

下载中的文件必须先落到 `.part` 临时文件，再在校验通过后原子移动到正式目录。

### 8.4 下载管理器

下载管理器负责：

- 创建下载任务
- 暂停 / 恢复 / 取消
- 断点续传
- 并发控制
- 进度上报
- 完整性校验（SHA-256）
- 失败重试

**下载状态机**

下载管理器内部状态：

- queued
- downloading
- paused
- verifying
- installed
- failed
- cancelled

UI 不直接暴露这些原始状态，而是映射成第 5.4 节定义的产品状态。

### 8.5 运行时管理器

运行时管理器负责托管 `node-llama-cpp` 的模型 / context / session 生命周期。

**运行时职责**

- 初始化运行时
- 加载模型
- 创建上下文与 chat session
- 写入日志
- 就绪检查
- 停止运行时
- 在模型切换时释放当前会话并载入新模型

**运行时默认值**

默认由系统控制，普通用户不直接编辑：

| 配置项 | 默认策略 |
| --- | --- |
| 运行方式 | 应用内托管（in-process） |
| `ctx-size` | 使用系统默认推荐值 |
| `gpu-layers` | 自动 |
| 线程数 | 自动 |
| `flash-attention` | 支持时自动开启 |

### 8.6 本地模型配置绑定层

本地模型在产品层面必须表现为"一个可用模型"，但在系统层面实际由三类实体构成：

| 实体 | 作用 |
| --- | --- |
| Installed Artifact | 已下载的模型文件与运行时元数据 |
| Managed Local Config | 用户看到的本地模型条目（`configType: "managed-local"`） |
| Active Runtime | 当前运行中的本地模型运行时会话 |

绑定层负责将三者关联起来，保证：

- UI 只看到一个"本地模型"，显示为"本地模型 · Qwen3.5 4B"等友好名称
- 实际调用路由与运行时会话由系统推导，不显示给用户
- 用户不用填写接口地址和模型标识

## 9. 配置类型设计

### 9.1 配置类型定义

`LlmConfigType` 当前包含三种主路径值：

| 配置类型 | 用途 | 接口地址 | 用户可见入口 |
| --- | --- | --- | --- |
| `"builtin"` | 内置远程模型（Kimi、OpenAI 等） | 由 preset 决定 | 通用弹窗 |
| `"custom"` | 用户自定义远程模型 | 用户填写 | 通用弹窗 |
| `"managed-local"` | **系统托管本地模型** | **系统自动管理，不暴露** | **专用本地模型页面** |

### 9.2 managed-local 类型规则

- **只能通过专用本地模型页面的"添加并下载"创建**，不通过通用模型弹窗。
- **内部调用路由由运行时管理器动态绑定**，不存储用户可编辑的接口地址。
- **不需要用户填写 API Key**。
- **不需要用户填写模型标识**，由系统根据安装记录自动推导。
- **在通用模型列表中不可编辑连接参数**，仅显示模型名称和运行状态。

### 9.3 历史兼容说明

历史上如果存在自行在外部启动 `llama-server` 或其他兼容推理服务的配置，可作为迁移兼容场景处理：

1. 不作为普通用户使用本地模型的入口。
2. 不影响 `managed-local` 的一键主路径。
3. 这类场景应被视为自托管兼容能力，而不是产品默认流程。

### 9.4 通用模型列表中的展示规则

托管本地模型出现在通用模型列表时，遵守以下规则：

| 场景 | 行为 |
| --- | --- |
| 列表展示 | 显示"本地模型"标签 + 模型名称 + 运行状态，不显示 endpoint |
| 点击编辑 | 跳转到专用本地模型页面，不打开通用编辑弹窗 |
| 启用/禁用 | 正常操作，与远程模型行为一致 |
| 删除 | 跳转到专用本地模型页面执行卸载流程 |
| 测试连接 | 由系统自动通过运行时管理器的就绪检查完成，不需要用户看到 URL |

### 9.5 系统内部关系

1. 用户通过专用本地模型页面选择并下载模型。
2. 系统自动创建 `configType: "managed-local"` 的模型配置。
3. 配置中的内部运行时句柄和请求模型名**由运行时管理器在启动时动态绑定**，不依赖用户输入。
4. LLM 使用层只消费"已启用的模型"这一结果，不区分配置来源。
5. 用户在通用模型列表中看到的是"本地模型 · Qwen3.5 4B"等友好名称，**不显示 `127.0.0.1` 地址或端口号**。

## 10. 数据模型设计

### 10.1 本地模型目录项

目录项至少包含：

- `id`
- `displayName`
- `family`
- `parameterSize`
- `qualityTier`
- `recommended`
- `format`
- `quantization`
- `downloadUrl`
- `fallbackRepositories`
- `estimatedDownloadSizeGiB`
- `estimatedRuntimeMemoryGiB`
- `license`
- `verifiedAt`

### 10.2 已安装制品

已安装制品记录至少包含：

- `artifactId`
- `artifactType`（model）
- `sourceModelId`
- `version`
- `filePath`
- `fileSize`
- `checksum`
- `installedAt`
- `status`

### 10.3 用户可见的本地模型配置

用户可见配置记录至少包含：

- `configId`
- `configType`（固定为 `"managed-local"`）
- `displayName`
- `installedArtifactId`
- `status`
- `enabled`
- `createdAt`
- `updatedAt`

其中 `installedArtifactId` 是关键字段，普通用户不感知，但系统通过它恢复真实连接关系。配置中不存储用户可编辑的 endpoint 或 API Key。

## 11. 异常与恢复设计

### 11.1 磁盘空间不足

- 阻止安装继续执行。
- 明确告诉用户还差多少可用空间。
- 推荐更小模型，而不是先让用户修改复杂参数。

### 11.2 内存资源不足

- 对较大模型显示明显提示。
- 推荐用户改用 Qwen3.5 4B。
- 不在默认路径中要求用户理解量化和上下文长度。

### 11.3 下载中断

- 保留部分下载文件。
- 应用重启后自动恢复。
- 提供单击继续下载。

### 11.4 校验失败

- 删除损坏文件。
- 记录失败原因。
- 自动重新下载或提供一键重试。

### 11.5 运行时启动失败

- 保留已安装模型文件与运行时元数据。
- 不删除安装记录。
- 在 UI 中显示"需要处理"，并提供单击重试启动。

### 11.6 仓库不可用

- 自动切换到预先验证过的备用仓库。
- 不要求用户重新选择模型。
- 尽量不把技术错误直接暴露为复杂术语。

## 12. 安全与隐私要求

1. 本地模型运行时默认在应用主进程内托管，不暴露外网访问。
2. 托管本地模型不需要 API Key，内部调用路由不向用户展示。
3. 下载内容必须通过 SHA-256 校验。
4. 运行日志保留在本地，不主动上传。
5. 删除模型时应允许删除模型文件、运行时缓存和日志。

## 13. 高级模式

高级模式不是默认入口，只用于少量需要调优的用户。

高级模式可考虑开放：

- `ctx-size` 覆盖
- `gpu-layers` 覆盖
- 线程数覆盖
- 手动重启运行时
- 日志导出
- 运行参数诊断

高级模式必须满足两个条件：

1. 默认隐藏。
2. 不破坏一键使用的主路径。

## 14. 首批内置模型

首批只提供两款经过验证的本地模型下载项。

| 模型 | 定位 | 推荐量化 | 下载大小 | 预计内存 | 主仓库 |
| --- | --- | --- | --- | --- | --- |
| Qwen3.5 4B | 默认推荐，适合多数设备 | Q4_K_M | 约 2.6 GiB | 约 5.0 GiB | `lmstudio-community/Qwen3.5-4B-GGUF` |
| Qwen3.5 9B | 更高质量，适合资源更充足设备 | Q4_K_M | 约 5.4 GiB | 约 9.5 GiB | `lmstudio-community/Qwen3.5-9B-GGUF` |

### 14.1 Qwen3.5 4B

- 文件名：`Qwen3.5-4B-Q4_K_M.gguf`
- 下载地址：`https://huggingface.co/lmstudio-community/Qwen3.5-4B-GGUF/resolve/main/Qwen3.5-4B-Q4_K_M.gguf`
- 备用仓库：`unsloth/Qwen3.5-4B-GGUF`

## 16. 总结

本地模型是一种被应用托管的能力。

- 用户只负责选择模型并点击一次添加按钮。
- 下载、安装、运行、配置、绑定、启用与恢复都由系统自动完成。
- 用户在任何界面中都不需要看到内部运行路由、接口协议或 API Key。
- 托管本地模型通过 `configType: "managed-local"` 与系统中的其他模型类型共存，拥有独立的专用管理页面。
